兼容性、会话恢复与账号说明

Copilot、Claude、Kimi 和 Qwen 支持恢复其提供的会话上下文与历史消息。DeepSeek Harness 仅恢复上下文 · 不回放旧消息。AgentLink 会保留本地已保存的消息；切换 Agent 不会把对话迁移到另一个服务商。

Claude 需要 claude-agent-acp 适配器；Kimi 使用当前 JavaScript 版 CLI 和 kimi login，不是已归档的 Python CLI；Qwen 通过 qwen --acp 连接。DSH 版本要求及详细配置见兼容性指南。

账号、模型权限、费用、推理选项、执行权限及图片支持取决于各 Agent 和服务商。新接入的 Agent 可能需要同时更新应用和 Bridge。

03 / 开始连接

装好两端，连接一次。

准备一部 Android 手机、一台装有 Python 3.11+ 和 Git 的电脑，以及至少一个已安装、已认证的编程 Agent。电脑需要保持唤醒、联网，并运行 Bridge。

  1. 01 / 手机

    安装 AgentLink。

    从 AgentLink Releases 下载最新 Android APK，包括预览版。更新时使用相同签名渠道覆盖安装，保留已保存的聊天。

    下载 Android APK ↗
  2. 02 / 电脑

    启动 Bridge 与 Web。

    先安装你选择的 Agent，并在电脑上登录。新版 Server 的 start 命令也会启动本机 Web 工作台。一个 Bridge 可以发现多个 Agent。

    Windows 快速启动 ↓
  3. 03 / 连接

    扫码，选好项目。

    打开 Machines → Scan QR，核对确认码并在电脑上批准配对。然后在 Chats 选择电脑、Agent，以及这台电脑上的项目路径。

    查看配对指南 ↗
Windows PowerShell · 首次配置电脑端

在你希望存放 AgentLink 的目录运行。以下命令安装的是 Bridge，不包含各个编程 Agent。

git clone https://github.com/gongpx20069/android-agent-link.git
cd android-agent-link
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .\bridge
.\.venv\Scripts\python.exe .\bridge\run.py start

如果出现 Dev Tunnels 登录提示，按提示完成认证。保持终端运行；新版 stdlib Server 会显示手机配对二维码、本机 Web 网址及访问码。下次运行最后一条命令即可，无需额外加 --web。

其他环境与完整配置 ↗
浏览器工作台 · 本机与 VM 聊天

新版 stdlib Bridge 的 start 默认包含 Web。打开输出的本机网址，通常为 http://127.0.0.1:4318，输入 Web 访问码即可。只需后台 Server 时使用 start --no-web；端口冲突可用 --web-port 0。首次没有工作目录时，增加 --workspace-root C:\Repos 可允许注册其下的已有目录。

统一搜索本机与 VM 聊天，按电脑筛选，通过拖动或 Alt + 上／下排列顺序。状态变化不会重排 Web 聊天。可以发送文字、查看工具详情、处理权限审批和问答。首版读取 Server 保留的共享历史；图片仍用 Android，原生历史会话选择仍用 Android 或终端。

在电脑管理中粘贴 VM 的当前配对链接，核对目标后提交，并在 VM 上确认。每台 VM 都需要新版 Bridge；不需要本地网页时可加 --no-web。浏览器只连接本机网关，工作仍在各台 VM 上执行。远程凭据保存在网关电脑的用户私有文件中，不是加密存储；不要把 Web 端口公开到隧道。

一台 VM 离线不会阻塞其他电脑。发送结果不确定时不会自动重试，应先检查回执再决定是否重发；关闭网页不会取消任务。仅更新 APK 不会更新电脑端 Bridge。

网页配置与使用边界 ↗
可选 · 也在终端里继续聊天

等待正在执行的任务结束，再用 Ctrl+C 停止服务。在同一个仓库目录安装终端组件，然后重新启动：

.\.venv\Scripts\python.exe -m pip install -e ".\bridge[interactive]"
.\.venv\Scripts\python.exe .\bridge\run.py start --interactive

在 Android 打开你的聊天；终端里可用 /chats 切换聊天。这是 AgentLink 的共享终端，不是对独立运行的厂商 CLI 的镜像。

更新 APK，不等于更新了电脑端。

应用与 Bridge 需要分别升级。等远端任务结束后停止 Bridge，按更新指南更新仓库和安装，再重新启动。新装 Agent 后也请重新打开终端，让 Bridge 能从 PATH 找到它。

几个实用的答案。

阅读使用指南 ↗
必须安装 Mochi 或全部五个 Agent 吗？

不用。AgentLink 是独立 Android 应用与电脑端 Bridge，配置好一个编程 Agent 就可以使用。Mochi 和终端聊天都是可选的。

Agent 显示 missing 是什么意思？

Bridge 无法从自己的 PATH 找到对应 Agent 的可执行文件或所需适配器。请在电脑上安装，重新打开终端并启动 Bridge，再刷新机器页。Available 只代表找到可执行文件，不代表认证成功或模型可用。

安装缺失与列表没有选项是两回事。如果同一台电脑在 Machines 能看到某个 Agent、New session 却没有，请在问题反馈中提供应用和 Bridge 版本，以及隐去敏感信息的截图。

可以恢复任意已有会话吗？

只能恢复连接的 Agent 提供的会话，恢复能力也各不相同：DeepSeek Harness 能恢复上下文，但不能回放外部会话的旧消息。切换 Agent 不会把一个服务商的对话迁移到另一个服务商。

可以关闭应用，或者让电脑休眠吗？

电脑应保持唤醒并运行 Bridge。关闭手机界面不等于取消远端任务，但 Android 后台更新有时间限制。重新打开 AgentLink 后，可重连并确认任务的实际状态。

可选：可以让 Mochi 成为语音入口吗？

可以。在 Mochi Tools → AgentLink 打开 AgentLink，在原生界面确认限定范围的权限，再启用 Provider、Tools 与 AgentLink Skill。Mochi 可以发现已授权工作区、创建或继续共享聊天、发送任务并读取结果。

凭据留在 AgentLink，不进入 Mochi 分享。由 Mochi 使用的结果会发送给其模型服务。执行审批仍由人决定；控制仅在前台开放，不向定时 Agent 或子 Agent 开放。后台结果补收受 Android 调度限制，请保持两款应用和 Bridge 更新。
